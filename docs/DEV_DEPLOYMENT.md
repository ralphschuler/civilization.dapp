# Isolated development Mini App

Production stays on its own HTTPS origin, port 31057, database, and proxy. Every deployment must set `CIVILIZATION_ENV` explicitly: `production` for the active stack and `development` only for the separate Dev stack in `deploy/truenas.dev.example.yaml` on host port 31058.

The Dev Mini App uses a distinct Dev World-App application, HTTPS origin, PostgreSQL service/volume/database, and World Chain **Mainnet (480)** test contract. Dev means isolated state, not a testnet: transactions and WLD are real. Never use Sepolia (MiniKit device transactions do not support it) or the production proxy. The runtime refuses Dev if its Mini App identity, origin, database, or contract isolation is invalid.

Deploy in this order: deploy and verify the isolated contract; configure the Dev Mini App with its HTTPS origin; provide the runtime values below; start PostgreSQL; wait for its healthcheck; run the migration job; then start the app. `GET /api/healthz` checks liveness and `GET /api/readyz` must return 200 before routing traffic. On an allowlisted physical World App device, complete WalletAuth and then the separately-clicked Mainnet transaction. Browser/GitHub Pages cannot validate native transport or server-backed flows.

Rollback means remove the Dev route/app workload and retain the Dev database for diagnosis; do not point Dev traffic at production. Roll back a Dev image only after its schema compatibility is confirmed. No Portal, DNS, contract, secret, or production change is made by this repository.

Set `CIVILIZATION_ENV=development`. The app reads only `DEV_WALLET_AUTH_URL`, `DEV_WORLD_APP_ID`, `DEV_CIVILIZATION_CONTRACT_ADDRESS`, `DEV_CIVILIZATION_CHAIN_ID`, and `DEV_CIVILIZATION_WORLD_TOKEN_ADDRESS`; it ignores the production-named World values. Set `DEV_PGHOST`, `DEV_PGDATABASE`, and `DEV_PGUSER`, and make the matching `PGHOST`, `PGDATABASE`, and `PGUSER` values identical for the database client. The Dev values must be distinct from production; the contract must not be the production proxy. Required protected inputs are the database password, deployed Dev contract address, a 32+ character `WALLET_AUTH_RATE_LIMIT_SECRET`, and the exact `WALLET_AUTH_TRUSTED_PROXY_HOPS`. Configure the ingress to replace `X-Forwarded-For` and append that number of trusted proxy addresses. Set the same database password as `PGPASSWORD` for the app/migration process and `POSTGRES_PASSWORD` for PostgreSQL initialization. The Portal must allowlist the Dev origin and Dev contract. GitHub Pages remains a walletless UI preview, not this Mini App.

## World Chain deployment recovery

If a contract-creation receipt succeeds but the RPC briefly returns `0x` for its code, the runner now polls a small bounded number of times and then stops safely. Do not rerun a normal send after any nonce drift: normal `--send` remains fail-closed and requires the reviewed deployer nonce exactly.

For the specific case where an earlier creation is known to have succeeded, first independently verify the reviewed plan, current pending nonce, and every planned address. Then rerun the same reviewed command with its normal exact confirmation and `--send --resume`. Resume accepts only the nonce-derived contiguous prefix: every adopted address must match the compiled runtime after normalizing only compiler-declared immutable byte ranges, with all occurrences in each immutable-reference group carrying identical bytes, and every later planned address must be empty. Empty immutable-reference groups are rejected. The runner requires a compiled runtime artifact for every adopted step. Before creating the registry it also derives the proxy's first child `ProxyAdmin`, requires the EIP-1967 admin slot and every proxy immutable occurrence to bind that exact address, and compares the child's unmodified on-chain `keccak256` codehash exactly with the compiled runtime hash (so a future child immutable cannot be masked), then verifies timelock ownership. The manifest records the real on-chain runtime codehash for each adopted or deployed contract and deliberately contains no invented transaction hash. Any codehash mismatch, malformed immutable metadata or runtime length, nonce drift, or address gap stops before another transaction is submitted.
